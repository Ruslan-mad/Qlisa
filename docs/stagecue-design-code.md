# Дизайн-код интерфейса StageCUE

## Цель интерфейса

Интерфейс — не медиаплеер, а рабочее место оператора шоу: следующая команда, текущая команда и безопасная остановка всегда считываются быстрее, чем второстепенные настройки. Информация о cue, воспроизведении и контроле собрана в одном окне без переходов между приложениями.

## Каркас основного окна

```text
┌──────────────────── project header / file menu ──────────────────────────┐
│ название шоу [• несохранено]                         Settings  Video Out │
├──────────────────── верхняя панель действий ─────────────────────────────┤
│ Audio  Video  Wait  Note  Group  GO  STOP  OSC*  Delete                  │
├───────────────────────────┬─────────────────────────────────────────────┤
│                            │ Properties                                   │
│ CueList                    │ ─ название / комментарий / PreRoll           │
│ №  тип  название  comment  │ ─ громкость, устройство, каналы, дисплей      │
│    duration  PreRoll state │ ─ Mix tracks, repeat, after-end               │
│                            │ ─ Parameters / Triggers*                      │
│  ▶/▼ Group                 │                                               │
│  01  Audio …               │                                               │
│  02  Video …               │                                               │
├───────────────────────────┴─────────────────────────────────────────────┤
│ TIMER: state · file · elapsed/remaining · seek/progress · incoming LTC* │
├──────────────────────────── control bar ─────────────────────────────────┤
│                         GO     PAUSE     STOP TRACK     STOP ALL          │
└─────────────────────────────────────────────────────────────────────────┘
* Появилось в поздних релизах или зависит от включённой функции.
```

Точное положение может меняться с размером окна, но источник прямо фиксирует пять зон: верхняя панель, CueList, свойства выбранного объекта, Timer и нижняя панель управления.

## Иерархия и расположение элементов

| Зона | Элементы и правило |
| --- | --- |
| Заголовок/файл | Имя проекта; точка рядом с ним — несохранённые изменения. Файл-операции (New, Open, Save, Save As, Recent). |
| Верхняя панель | Создание содержимого до старта: Audio, Video, Wait, Note, Group, GO, STOP, позднее OSC; доступ к Settings и Video Out. Действия — компактные, однотипные и всегда наверху. |
| CueList | Главное, самое широкое рабочее поле. Столбцы: номер, тип, название, длительность, PreRoll, состояние; комментарий расположен между названием и таймером/временной частью. Вложение обозначается отступом и шевроном группы. |
| Properties | Контекстная панель выбранной строки: показывает только релевантные параметры — например, аудиовыходы для Audio, дисплей для Video, триггеры для track/group. |
| Timer | Крупные временные значения, имя файла, Ready/Playing/Pause и полоса прогресса. Полоса аудио интерактивна (click/drag seek). LTC-индикатор расположен в нижней части UI. |
| Control bar | Самые важные действия вынесены вниз крупными кнопками: GO, PAUSE, STOP TRACK, STOP ALL. STOP ALL должен быть визуально доступен как аварийное действие. |
| Video Out | Отдельное чёрное полноэкранное окно на выбранном экране. Никаких рамок и курсора; чёрный фон сохраняется после stop. |

## Цвет, статусы и темы

| Сущность | Код поведения |
| --- | --- |
| Тёмная тема | Привычная базовая тема StageCUE; ориентирована на рабочие мониторы во время шоу. |
| Светлая тема | Добавлена в 3.8.3 как системное оформление; выбор — в Settings. Компоненты и статусные цвета не меняют смысл. |
| Selected cue | Синий; имеет приоритет над пользовательским цветом строки. |
| Playing cue | Ярко-зелёный; слева от номера — крупный зелёный треугольник. Должен быть различим при длинном списке. |
| Ready / Playing / Pause | Явные текстовые состояния в таймере, не только цвет. |
| GO | Основная зелёная кнопка. При защите от повторного нажатия — красная обводка, не отключающая остальные команды. |
| PAUSE | Жёлтая кнопка; один и тот же контроль временно останавливает и продолжает. |
| STOP TRACK / STOP ALL | Деструктивные/аварийные действия должны быть визуально отделены от GO и иметь постоянное положение. |
| Custom cue color | Спокойные полутоновые цвета для сцен, блоков или типов контента; только вспомогательная категоризация. |
| Comments | Обычный, не тонкий курсив (изменено в 3.8.3) для быстрого чтения. |

## Интеракции CueList

### Выбор и фокус

- Курсор — это текущая выделенная строка; GO запускает именно её.
- После запуска курсор перемещается к следующей строке.
- Использовать `↑/↓` для последовательного навигационного фокуса, `←/→` — для collapse/expand группы.
- В 3.8.1 список автоматически прокручивается, удерживая playing cue и, по возможности, три следующих cue в видимой области.

### Drag-and-drop

- Трек между строками: предварительная линия вставки.
- Трек на группу: сама группа подсвечивается рамкой.
- Группа между группами: предварительная линия; перетаскивание группы внутрь другой запрещено.
- Такое предварительное отображение обязательно: оно снижает риск ошибочной перестановки в шоу-файле.

### Редактирование и безопасность

- Двойной щелчок по имени, PreRoll, комментарию и after-end icon — локальное редактирование, без модального окна.
- Актуальная UX-логика: двойной щелчок по cue **не запускает** воспроизведение. Запуск — GO/Space или назначенный внешний контроллер.
- Блокировка повторного GO — видимая красная рамка на кнопке, а не скрытая задержка.
- STOP TRACK действует строго на playing track под курсором; STOP ALL всегда остаётся доступен.

## Компонентные правила

### Cue row

Минимальный набор содержимого: `state glyph → номер → type glyph → название → комментарий → duration/timer → PreRoll → end behavior`.

- Номер автоматический; не требует ручного редактирования.
- Воспроизводимый трек добавляет большой play-indicator слева от номера.
- Группа показывает шеврон и отступ у дочерних треков.
- Пользовательские цвета не должны скрывать selected/playing status.
- Комментарий нужен для операторской инструкции, поэтому контраст и обычное начертание важнее декоративности.

### Properties panel

Компоненты организуются по типу cue, а не как один длинный универсальный form:

- **Media:** название, комментарий, PreRoll, громкость, Mix tracks, Repeat, after-end.
- **Audio:** device + физические channels.
- **Video:** display / projector / NDI.
- **Wait:** duration + быстрые значения, если доступны.
- **Group:** Mix tracks, after-end, триггеры.
- **GO:** цель, PreRoll, `Stop all previous`; имя вычисляется по цели.
- **STOP:** цель, PreRoll, FadeOut, CrossFade, after-end.
- **OSC:** отдельное многострочное поле команды.
- **Triggers:** отдельная вкладка, а не смешивание с параметрами воспроизведения.

### Внешнее состояние

- Входящий LTC — компактный постоянный индикатор: таймкод при сигнале, прочерки без сигнала.
- MIDI/OSC mapping должны сообщать выбранный вход и режим «ожидание сообщения» до привязки.
- Video Out визуально отделён от операционного UI, чтобы на проектор не попали служебные окна.

## Практические требования к аналогу

1. Всегда сохранять visible current cue + минимум несколько следующими в длинном списке.
2. Не привязывать важный статус только к цвету: play icon, текст Ready/Playing/Pause и красная рамка GO — отдельные сигналы.
3. Любая операция, меняющая структуру show-file, должна давать предварительный target (drop line / group outline).
4. Вывести аварийный STOP ALL в постоянную нижнюю панель и поддерживать `Esc`.
5. Оставить свойства контекстными; Audio, Video, STOP и OSC не должны показывать нерелевантные поля.
6. Сохранять чёрный fullscreen output после завершения video — это часть сценической логики, а не ошибка UI.
