# Задержка GO до первого прогресса медиа

Замер выполнен на Qlisa 1.5.12, 2026-10-07, исходный код `30fd39a`. Каждый из 16 вариантов прошёл 21 запуск: первый запуск в новом процессе и 20 повторов с новым cue и stream. Все 336 запусков успешны.

GO вызывался напрямую через `Transport::go_by_id`, без клика в интерфейсе, JavaScript dispatch или IPC. Для аудио измерялось время до первого `voice_position_ms > 0`, то есть до того, как реальный callback аудио потребил кадры. Master gain был равен нулю. Устройство работало через WasapiShared на 48 кГц с буфером драйвера по умолчанию; ASIO не использовался.

Для изображений и видео измерялось время до первого НЕЧЁРНОГО кадра композиции по timestamp захвата compositor при 30 FPS. Alpha не участвует в критерии. Timestamp не включает позднее прибытие PBO readback. Частота выборки добавляет квантование до 33 мс плюс расписание рендера. Поэтому различия visual-замеров меньше примерно 33 мс недостаточны, чтобы заключить, что более крупный файл запускается быстрее. Эти результаты не показывают точный момент появления кадра на мониторе или звука на динамике.

В этих данных размер файла слабо предсказывает задержку. WAV 180 с в 18 раз больше WAV 10 с, но медиана ниже: 32,8 против 41,4 мс. JPEG 4K Q95 весит 4,53 MiB против 0,53 MiB у Q30; медиана выше (344,7 против 103,0 мс), хотя разрешение одинаковое. H.264 1080p 60 с в 7,5 раза больше восьмисекундного файла, но медиана ниже (177,8 против 194,0 мс). Разница 16,2 мс меньше шага visual-выборки и не подтверждает преимущество большего файла. Исходный HEVC 4K весит 190,02 MiB, а конвертированный H.264 — 22,79 MiB; медианы близки (195,1 и 193,9 мс), а разница 1,2 мс также меньше шага выборки. У конвертированного файла в сводке замера указано разрешение 608×1080.

## Условия и ограничения

- Один видеовыход 1280×720.
- CPU: Intel Core i7-12700K, 20 логических процессоров; GPU: RTX 3080; накопитель: Samsung 980 PRO NVMe.
- В видеозаписях наблюдался backend декодирования `d3d11va-copy`; этот замер не определяет, какой физический GPU выполнял декодирование.
- Windows file cache не очищался. Поэтому `First` означает первый запуск приложения для данного файла, но не гарантирует холодное чтение с накопителя.
- Замер исключает путь через GUI, JavaScript и IPC. Он не измеряет физическое начало вывода через видеовыход или акустический выход.

## Повторный запуск

Из корня проекта соберите пример:

```powershell
cargo build --release --locked --features asio-support --example go_latency_bench
```

Затем запустите один fixture, подставив свой путь к machine audio config:

```powershell
$AudioConfigPath = 'путь к machine audio config'
target\release\examples\go_latency_bench.exe tmp\go-latency\fixtures.json tmp\go-latency\rerun.json --audio-config $AudioConfigPath --repeats 21 --only audio-wav-10s
```

`--repeats 21` включает первый запуск и 20 повторов. Имена остальных вариантов находятся в `fixtures.json`.

Полные сводки и записи запусков находятся в локальном игнорируемом каталоге `tmp/go-latency`; здесь приведены только агрегированные результаты.
